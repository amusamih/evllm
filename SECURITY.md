# Security boundaries and threat model

The table summarizes the threats addressed by the implementation, the corresponding controls and the
risks that remain outside those controls.

| Threat                                                | Implemented control                                                                                                                                                                                                                                                                                                                                                                                | Remaining boundary                                                                                                                                                                                                                                               |
| ----------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Stolen participant or deployer key                    | A separate Sepolia wallet is used for each tested role. Signatures are bound to an exact scope, one-use nonce and expiry, and deployment is separated from governance. The local authenticated interface also binds its controlled credential to one configured public wallet address.                                                                                                             | A compromised host or wallet can still misuse its active key; the affected credential must be suspended and rotated.                                                                                                                                             |
| Unauthorized state-changing action                    | Read and command paths are separated. Participant commands bind the affected resource, version and intended effect to the signed request, and the LLM has no command tools.                                                                                                                                                                                                                        | A valid signature cannot prove that the participant understood the transaction.                                                                                                                                                                                  |
| API abuse or resource exhaustion                      | Requests have a 16 KiB limit, bounded dependency checks, bounded session and rate-limit stores, per-client-address rate limits, finite retries and structured errors. The demonstration server binds to loopback by default.                                                                                                                                                                       | Distributed denial-of-service protection, production identity integration and edge controls are not included.                                                                                                                                                    |
| Secret or plaintext leakage                           | Logs use structured redaction and generic errors. Assistant responses are submitted with provider storage disabled, and metrics contain no keys or protected plaintext.                                                                                                                                                                                                                            | Compromise of the operating system, browser, wallet or model provider remains outside these controls.                                                                                                                                                            |
| Repository outage or withholding                      | A byte-identical encrypted replica supports verified recovery of decision-critical packages.                                                                                                                                                                                                                                                                                                       | The evaluated same-host configuration does not demonstrate organizational independence or a service-level guarantee.                                                                                                                                             |
| Corrupted backup or cross-organization restore        | Backups are bound to one repository namespace and verified by exact length and SHA-256 digest. Existing objects cannot be overwritten with different bytes.                                                                                                                                                                                                                                        | Independent backup-media custody and a separate disaster-recovery site are not included.                                                                                                                                                                         |
| Encrypted-package tampering                           | AES-256-GCM authentication and checks of the envelope digest, length, package and signatures reject altered packages.                                                                                                                                                                                                                                                                              | Cryptographic integrity does not establish that the submitted information is true.                                                                                                                                                                               |
| Replay, key substitution or decryption-key compromise | Contract nonces are retained on chain, and consumed key-operation authorizations are retained in PostgreSQL before key use begins. Grant and controller-key changes bind the SHA-256 digest of canonical RSA SPKI material to the authorization, an organization identity signature and an RSA-PSS possession proof. Key capabilities are one-use and expired or revoked credentials are rejected. | Other protected-workflow state is process-local in the evaluated composition; restart-safe operation requires durable state adapters. A failed or uncertain key operation requires a new authorization, and a lost final decryption key cannot be reconstructed. |
| Blockchain reorganization or stale application view   | Confirmed checkpoints and a rollback-and-replay projector rebuild application views from the replacement confirmed event history.                                                                                                                                                                                                                                                                  | Finality and remote procedure call provider availability remain blockchain dependencies.                                                                                                                                                                         |
| Malicious contract behavior or dependency             | Pinned compilers and dependencies are combined with unit, property, fuzz, invariant and reentrancy testing, coverage measurement and Slither analysis.                                                                                                                                                                                                                                             | Testing and static analysis cannot prove the absence of every vulnerability.                                                                                                                                                                                     |
| Deployment drift                                      | A generated artifact manifest, local rehearsal, separate deployment and governance confirmation, explorer verification and explicit approval bind the deployed contracts to the reviewed build.                                                                                                                                                                                                    | Mainnet deployment and production governance are not included.                                                                                                                                                                                                   |

No unresolved high- or medium-impact Slither finding is accepted. Each low or informational finding
is documented with its review rationale. Static analysis complements testing but does not constitute
a security certification.
